# Blueprint: Practice Intelligence SaaS

## คำจำกัดความ

Template ในระบบนี้หมายถึง **แม่แบบระบบทั้งบริษัท (System Blueprint)** ไม่ใช่เฉพาะแม่แบบเอกสาร บริษัทใหม่ต้องสามารถสร้างพื้นที่ของตนเองจาก Blueprint แล้วเลือกโมดูล ขั้นตอน สิทธิ ตราสินค้า และข้อมูลที่ต้องใช้ได้ โดยข้อมูลของแต่ละบริษัทไม่ปะปนกัน

## ผู้ใช้งานสี่ระดับ

1. **เจ้าของแพลตฟอร์ม** — สร้างบริษัท กำหนดแพ็กเกจ เปิดโมดูล ดูการใช้งาน และควบคุมรุ่นของ Blueprint
2. **ผู้ดูแลบริษัท** — จัดการผู้ใช้ สิทธิ ขั้นตอน ช่องข้อมูล เอกสาร และตราสินค้าของบริษัทตนเอง
3. **ผู้ปฏิบัติงาน** — ใช้ CRM งาน เอกสาร การฝึกอบรม การบริการ และรายงานตามสิทธิ
4. **ลูกค้าของบริษัท** — ใช้ Client Portal เฉพาะบัญชีของตนเอง

## ส่วนประกอบของ System Blueprint

- โครงเมนูและโมดูล
- โครงข้อมูลและช่องข้อมูล
- บทบาทและสิทธิ
- ขั้นตอนทำงานและการอนุมัติ
- แม่แบบเอกสารและรุ่นเอกสาร
- งานอัตโนมัติและการแจ้งเตือน
- Dashboard และตัวชี้วัด
- Client Portal และสิ่งที่ลูกค้าเห็น
- Knowledge Center และสิทธิการเข้าถึง
- รูปแบบตราสินค้า ภาษา และข้อความระบบ

## สถาปัตยกรรมข้อมูล

ข้อมูลทุกตารางที่เป็นข้อมูลธุรกิจต้องมี `tenant_id` และทุกคำสั่งอ่านหรือเขียนต้องตรวจสมาชิกของบริษัทจากผู้ใช้ที่เข้าสู่ระบบบนฝั่งเซิร์ฟเวอร์ ห้ามรับ `tenant_id` จากหน้าจอแล้วเชื่อถือโดยตรง

ลำดับข้อมูลหลัก:

`Platform → Blueprint Version → Tenant Company → Subscription → Enabled Modules → Roles & Permissions → Records → Audit Log`

ไฟล์ต้องแยกด้วยพื้นที่จัดเก็บของบริษัท เช่น `tenant/{tenant_id}/...` และข้อมูลตรวจสอบย้อนหลังต้องบันทึกผู้กระทำ เวลา บริษัท รายการ และรุ่นข้อมูล

## P0 — แกน SaaS ที่ต้องทำก่อนเปิดบริษัทที่สอง

- Company Provisioning และสถานะ Active/Suspended
- บัญชีผู้ใช้ สมาชิกบริษัท และบทบาท
- การแยกข้อมูลตาม `tenant_id` ในทุกโมดูล
- Module Catalogue และการเปิด/ปิดโมดูลรายบริษัท
- System Blueprint ที่มีรุ่นและสามารถนำไปสร้างบริษัทใหม่
- Branding และ Navigation รายบริษัท
- Audit Log กลาง
- การสำรองและส่งออกข้อมูลรายบริษัท

### เกณฑ์รับงาน P0

- ผู้ใช้บริษัท A ไม่สามารถอ่าน แก้ หรือค้นข้อมูลของบริษัท B ได้ แม้แก้ URL หรือคำขอโดยตรง
- เจ้าของแพลตฟอร์มสร้างบริษัทใหม่จาก Blueprint ได้โดยไม่แก้โค้ด
- ผู้ดูแลบริษัทเปิดหรือปิดโมดูลและเพิ่มผู้ใช้ได้ตามแพ็กเกจ
- การเปลี่ยน Blueprint รุ่นใหม่ไม่แก้ข้อมูลเดิมย้อนหลังโดยอัตโนมัติ
- ทุกการเปลี่ยนสิทธิและการอนุมัติมี Audit Log

## P1 — เครื่องมือปรับระบบโดยไม่แก้โค้ด

- Form Builder ที่นำ Field Definition ไปแสดงในหน้าจอจริง
- Workflow Builder พร้อมเงื่อนไขและผู้อนุมัติ
- Task Automation และการแจ้งเตือน
- Document Builder และ E‑Signature Integration
- Dashboard Builder ตามบทบาท
- Import/Export และ Data Mapping

## P2 — SaaS เชิงพาณิชย์

- แพ็กเกจ ราคา การทดลองใช้ และ Subscription
- Usage Metering และ Billing
- Custom Domain และอีเมลของแต่ละบริษัท
- Marketplace ของ Blueprint/Module
- API/Webhook และ Integration Catalogue
- การบริหาร SLA, Support และสถานะระบบ

## สถานะระบบปัจจุบัน

มีโครง Registry สำหรับบริษัท โมดูล ช่องข้อมูล เอกสาร งาน และ Workflow แล้ว แต่ยังเป็น BIB-first implementation และยังไม่ผ่านเกณฑ์ P0 เพราะข้อมูลธุรกิจเดิมบางตารางไม่มี `tenant_id`, API ตั้งค่าบางส่วนยังอ้าง BIB โดยตรง, Field ใหม่ยังไม่สร้างหน้าจออัตโนมัติ และสิทธิอนุมัติยังไม่ได้ผูกกับสมาชิกบริษัทจริง

ดังนั้นห้ามนำบริษัทที่สองเข้ามาใช้ข้อมูลจริงจนกว่าจะเสร็จ P0 และผ่านการทดสอบการแยกข้อมูล
