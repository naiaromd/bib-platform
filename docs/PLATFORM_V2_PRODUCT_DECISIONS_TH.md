# ข้อตกลงการพัฒนา BIB Platform รุ่นใหม่

ปรับปรุงล่าสุด: 1 สิงหาคม 2569

## 1. สถานะระบบเดิม

- `/platform` เป็นระบบต้นแบบและแหล่งอ้างอิงข้อมูลเดิม
- หยุดเพิ่มโมดูลใหม่ลงในหน้าดังกล่าว ยกเว้นการแก้ข้อผิดพลาดสำคัญ
- ระบบรุ่นใหม่เริ่มที่ `/workspace` และจะย้ายผู้ใช้เมื่อผ่านการทดสอบ

## 2. หลักการออกแบบ

1. หน้าแรกแสดงงานที่ต้องทำ ไม่แสดงข้อมูลทุกประเภทพร้อมกัน
2. ผู้ใช้เห็นเฉพาะเมนู ข้อมูล และการกระทำตามบทบาท
3. ทุกข้อมูลสำคัญต้องมีเจ้าของ สถานะ ขั้นตอนถัดไป และประวัติการเปลี่ยนแปลง
4. ข้อมูลจริงเก็บฝั่งระบบ ไม่ใช้หน่วยความจำของเบราว์เซอร์เป็นแหล่งหลัก
5. แยกข้อมูลส่วนบุคคลของผู้รับบริการออกจากข้อมูลหลักฐานที่จะส่งให้ BIB
6. เปิดโมดูลในเมนูเมื่อเชื่อมข้อมูลจริงและมีผู้รับผิดชอบแล้วเท่านั้น

## 3. พื้นที่ใช้งาน

| พื้นที่ | ผู้ใช้หลัก | งานหลัก |
|---|---|---|
| BIB Workspace | ผู้บริหาร ฝ่ายขาย การตลาด Trainer และ After Sales | CRM นัดสาธิต ข้อเสนอ สัญญา ส่งมอบ และรายงาน |
| Client Portal | เจ้าของและผู้จัดการสถานประกอบการ | ผลงาน ทีม เครื่อง การรับประกัน บริการ และการสั่งซื้อ |
| Therapist Workspace | ผู้ปฏิบัติงาน | การบ้าน บันทึกเคส ภาพ เสียง การฝึกอบรม และผลตรวจ |
| Prospect Experience | ผู้สนใจและผู้ตัดสินใจ | หลักฐาน นัดสาธิต ข้อเสนอ และเอกสารที่ได้รับอนุญาต |

## 4. ลำดับข้อมูล CRM

`แหล่งที่มา → ผู้ติดต่อ → บัญชีลูกค้า → Lead → โอกาสขาย → กิจกรรม/งาน → นัดสาธิต → ข้อเสนอ → สัญญา → ลูกค้าที่ใช้งาน`

- Lead และ Contact ต้องแยกจากกัน
- Contact สามารถยังไม่มี Account ได้
- โอกาสขายต้องมีมูลค่า ความน่าจะเป็น วันที่คาดว่าจะปิด ขั้นตอนถัดไป และผู้รับผิดชอบ
- การเปลี่ยนขั้นตอนต้องสร้างประวัติกิจกรรม ไม่เขียนทับโดยไม่มีร่องรอย

## 5. ลำดับข้อมูลหลักฐาน Therapist

`การบ้าน → รหัสเคส → ความยินยอม → โปรแกรม/Protocol → ค่าก่อนทำ → ภาพก่อนทำ → บันทึกแต่ละครั้ง → ภาพหลังทำ → ค่าหลังทำ → เสียงสรุป → ตรวจโดยผู้จัดการ → ตรวจโดย BIB → Result Book`

- ไม่บังคับเก็บชื่อผู้รับบริการในพื้นที่ BIB
- ภาพและเสียงเก็บใน R2 ส่วนข้อมูลค้นหาและสถานะเก็บใน D1
- รูปต้องมีประเภทมุม ช่วงเวลา และการตรวจคุณภาพ
- เสียงต้องถอดเป็นข้อความและให้ผู้ส่งตรวจทานก่อนยืนยัน
- การใช้เพื่อการดูแล การวิเคราะห์ และการตลาดต้องมีความยินยอมแยกกัน

## 6. ขอบเขตการส่งมอบรุ่นแรก

### ต้องมี

- งานวันนี้
- รายชื่อลูกค้าและผู้สนใจ
- หน้ารายละเอียดบัญชีลูกค้าและประวัติกิจกรรม
- งานติดตามและนัดสาธิต
- โอกาสขายและขั้นตอนถัดไป
- การบ้าน Therapist แบบใช้โทรศัพท์
- ภาพ เสียง ข้อมูลผลลัพธ์ และคิวตรวจ
- สิทธิ์ระดับบริษัท บทบาท และบัญชีลูกค้า

### ยังไม่เปิดในเมนูรุ่นแรก

- การตั้งค่า SaaS แบบไม่ใช้ผู้พัฒนา
- ระบบคะแนนรางวัล Therapist
- การแนะนำ Protocol อัตโนมัติ
- การถอดเสียงอัตโนมัติเต็มรูปแบบ
- การเชื่อมระบบบัญชีและลายมือชื่อภายนอกแบบสมบูรณ์

รายการเหล่านี้ต้องต่อยอดจากข้อมูลจริงหลังการนำร่อง ไม่สร้างเป็นหน้าจำลองเพิ่มในรอบแรก
